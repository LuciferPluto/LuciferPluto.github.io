AXI协议学习总结

1 AXI的概述

1.1 AXI简介

AXI总线协议是 ARM 公司提出来的 AMBA 3.0 协议中最重要的部分，是一种面向高性能、高带宽、低延迟的片内总线。

1.2 AMBA的历史

年份 版本 说明
1995 AMBA 1.0 APB 外设总线以及 ASB 系统总线发布
1999 AMBA 2.0 AHB 系统总线发布，APB 总线升级为同步总线
2003 AMBA 3.0 高性能互联协议 AXI 发布，APB 总线扩展，AHB-LITE 协议发布
2010 AMBA 4.0 发布 AXI4 和 AXI-LITE

协议演进时间轴（原图）：横轴为时间（1995 / 1999 / 2003 / 2010，对应 V4 / V5 / V6 / V7），纵轴为 Performance（性能）与 Architecture（架构）。

时间 版本 协议
1995 V4 AMBA ASB、AMBA APB
1999 V5 AMBA 2 AHB、AMBA 2 APB
2003 V6 AMBA 3 AXI、AMBA 3 AHB-Lite、AMBA 3 APB
2010 V7 AMBA 4 AXI4、AMBA 4 AXI_Lite

1.3 AXI特性

  • 地址/控制操作与数据操作相位分离。
  • Byte Strobe 信号支持非对齐传输。
  • 每次突发传输只需要发送传输的首地址。
  • 分离的读、写通道支持低成本 DMA。
  • 支持 Outstanding 地址发送功能。
  • 支持乱序传输。
  • 方便集成寄存器 Stage 以满足时序要求。

2 AXI协议结构

2.1 AXI架构

  • AXI 的基本传输模式为突发传输（Burst）。
  • 五个数据通道（Channel），相当于独立的五条总线。
  • 每条通道都具有固定的方向性。
  • 通道以异步方式进行传输，包括独立的双向握手信号（Valid 和 Ready）。
  • 信源通过 Valid 信号指示数据或控制信息在该通道有效，信宿通过 Ready 信号指示该数据已经被获取。

读写通道组成：

操作 包含通道
读操作 AR 通道（读地址）、R 通道（读数据），共 2 个通道
写操作 AW 通道（写地址）、W 通道（写数据）、B 通道（写响应），共 3 个通道

通道结构（原图）：Master（Interface Master）通过 Addr and Ctrl 接口与 Slave（Interface Slave）连接，包括：

  • Read Address Channel：Addr and Ctrl → 地址与控制信息（Master → Slave）
  • Read Data Channel：Read Data（Slave → Master）
  • Write Address Channel：Addr and Ctrl（Master → Slave）
  • Write Data Channel：Write Data（Master → Slave）
  • Write Resp Channel：Write Resp（Slave → Master）

    架构要点：AXI 架构由五个通道组成，master 的写操作由写地址通道、写数据通道、写响应通道完成；Master 的读操作由读地址通道和读数据通道完成。每个通道都是独立的，由 master 的 valid 和 slave 的 ready 进行握手通信。

2.2 AXI通道握手

传输都是发生在 valid 和 ready 都有效的时刻。

读操作（Figure 1-4 Read burst）


ARADDR、ARVALID、ARREADY 属于读地址通道：

  • 在 T1 时刻 master 发出地址和 valid，但 slave 的 ready 拉低表示在忙；
  • 下一拍拉高表示可以接收命令；
  • 在 T2 时刻读命令有效。

RDATA、RLAST、RVALID、RREADY 属于读数据通道，同样，在 valid 和 ready 都为高的时刻传输才有效。

时序波形要点（T0 ~ T13）：

信号 波形要点
ACLK 全局时钟
ARADDR T1 发出地址 A
ARVALID T1 拉高，保持至握手完成
ARREADY T1 为低（忙），T2 拉高，读命令在 T2 有效
RDATA 在握手有效时刻依次输出 DA0 / DA1 / DA2 / DA3
RLAST 最后一个读数据时拉高
RVALID / RREADY 均为高时读数据传输有效

读操作依赖关系：单箭头表示没有明确要求先后顺序，双箭头有明确要求。要求读数据 valid（RVALID）一定要在读地址 valid（ARVALID）和 ready（ARREADY）之后。

ARVALID ────▶ RVALID
ARREADY ────▶ RREADY
（ARVALID/ARREADY 先于 RVALID 有效）

写操作（Figure 1-6 Write burst）

  • AWADDR、AWVALID、AWREADY 属于写地址通道；
  • WDATA、WLAST、WVALID、WREADY 属于写数据通道；
  • BRESP、BVALID、BREADY 属于写响应通道。

    时序要点（T0 ~ T10）：
信号 波形要点
ACLK 全局时钟
AWADDR T1 发出地址 A
AWVALID / AWREADY 写地址在 T2 时刻当两者都有效时生效
WDATA 数据分别于 T4 / T6 / T8 / T9 时刻有效，依次为 D(A0) / D(A1) / D(A2) / D(A3)
WLAST 最后一个写数据时拉高
WVALID / WREADY 均为高时写数据传输有效
BRESP 写响应在 T10 时刻有效（OKAY）
BVALID / BREADY 均为高时写响应有效

当 slave 接收到所有的写数据后才回应 master 一个 response。

写操作依赖关系：单箭头表示没有明确要求先后顺序，双箭头有明确要求（AWVALID/AWREADY → WVALID/WREADY → BVALID/BREADY 依次握手）。

3.8 AXI4.0新增信号

  1. AWQOS 和 ARQOS 代表着当前命令的优先级，用于总线仲裁；
  2. AWREGION 和 ARREGION：
    • 一方面给 transaction 标识 region，从而很方便的实现 logical address 到 physical address 的 address mapping。如一个 logical address 标识为不同的 region，就可以 mapping 到不同的物理地址上去，所以不需要 slave 用额外的 decoder 去支援不同的逻辑地址；
    • 另一方面通过划分 region，对某些 physical allocation 进行保护，比如某个 region 只能被 non-secure write，某个 region 只能被 secure write。
  3. AXI4 除去了 WID，对于写操作不能实现乱序了。

4 AXI突发操作

4.1 AXI突发类型

AXI 突发类型主要包括三种：FIXED、INCR、WRAP。由总线信号 AWBURST 和 ARBURST 来决定突发操作的类型。

Table 4-3 Burst type encoding

ARBURST[1:0] / AWBURST[1:0] Burst type Description Access
b00 FIXED Fixed-address burst FIFO-type
b01 INCR Incrementing-address burst Normal sequential memory
b10 WRAP Incrementing-address burst that wraps to a lower address at the wrap boundary Cache line
b11 Reserved - -

4.2 AXI的FIXED传输

AXI 的 FIXED 传输是指当 AWBURST/ARBURST 配置为 00 的时候，意思是在一个固定长度的突发，每个传输的地址都是相同的。这种突发传输用于重复访问相同的位置，比如装载和清空一个外设 FIFO。

4.3 AXI的INCR传输

AXI 的 INCR 传输是指当 AWBURST/ARBURST 配置为 01 的时候，在 INCR 传输中，每次传输的地址都是在前一个传输地址的基础上递增，递增的值取决于 Axsize。比如 Axsize=000，那表示每次传输大小是 1byte，那每次地址增加 1。

4.4 AXI的WRAP传输

4.4.1 WRAP的介绍

AXI 的 WRAP 传输是指当 AWBURST/ARBURST 配置为 10 的时候，在回环突发中，当地址增加到回环地址边界的时候地址会卷回回环地址段的第一个地址。

回环突发需要遵循两个限制：

  1. 起始地址必须和传输大小对齐；
  2. 突发长度必须是 2 / 4 / 8 / 16。

注：起始地址一定要与传输大小对齐的意思是：起始地址一定要是传输大小（byte 单位）的整数倍。

4.4.2 WRAP地址的计算

WRAP 地址的计算中最重要的是要计算出回环边界：

Boundary_addr = int(start_addr / (burst_size × burst_len) + 1) × (burst_size × burst_len)

在回环边界会回环到回环地段的首地址，首地址的计算方式：

First_addr = int(start_addr / (burst_size × burst_len)) × (burst_size × burst_len)

举例：一个 WRAP 操作

  • start address：0x04
  • Transfer size：32 bits
  • Burst length：4 transfers

计算过程：

边界地址 = (4/(4×4) + 1) × (4×4) = 0x10
首地址   = (4/(4×4)) × (4×4)     = 0x00

所以在 0x10 会回环到回环地段的首地址 0x00，本次操作对应的 Wrap_Boundary 为 0x0C，绕回地址为 0x00。

5 AXI的cache

5.1 Cache简介

AXI 对于系统级 cache 的支持是由总线上 AWCACHE 和 ARCACHE 实现的。这两个信号通过提供事务的可缓存、可高速缓存以及可分配属性来支持系统级 caches。

AWCACHE/ARCACHE 每一比特的含义：

比特位 含义
Awcache/Arcache[0] 表示 bufferable，Interconnect 可以先返回 response，只用在 write 操作。
Awcache/Arcache[1] 表示 Cacheable，对于写操作，可以有不同的 write merge；对于读操作，可以预读取。
Awcache/Arcache[2] Read allocate，用于读操作时 cache miss，他会先分配再读。
Awcache/Arcache[3] Write allocate，用于写操作时 cache miss，他会先分配再读外存，在 write-back 写回。

5.2 Cache读写机制

1) Write-through 和 write-back 的区别：

  • Write-through（直写模式）：数据更新的时候，同时写入 cache 和下一级存储；
  • Write-back（回写模式）：数据更新的时候，只写 cache；当数据被替换出来的时候才将被修改的 cache 数据写到下一级存储。

2) Allocate（针对 cache miss 时的处理）：

  • NO-allocate：不论读写，cache miss 的时候直接写下一级存储；
  • Read-allocate：读操作，cache miss 的时候在 cache 中分配一个空间，从下一级存储读取该数据到 cache 分配的这个空间，最后读取该值；
  • Write-allocate：写操作，cache miss 的时候在 cache 中分配一个空间，将数据先写入该位置，根据 write-back 还是 write-through 决定是否在写入下一级存储。

Memory Type 对照表（ARCACHE[3:0] / AWCACHE[3:0] 配置）：

ARCACHE[3:0] AWCACHE[3:0] Memory Type

0001 0001 Device bufferable
0010 0010 Normal Non-cacheable Non-bufferable
0011 0011 Normal Non-cacheable Bufferable
1010 0110 Write Through No Allocate
1110 (0110) 0110 Write Through Read Allocate
1010 1110 (1010) Write Through Write Allocate
1110 1110 Write Through Read & Write Allocate

6 AXI原子操作

6.1 Lock操作

Lock 是指 master 独占一个 slave 直至一次完整操作完成。

  • 只存在于 AXI3 协议中，AXI4 将该操作移除。
  • AXI3 和 AXI4 的 AWLOCK/ARLOCK 配置如下表所示。

Table 6-1 Atomic access encoding（AXI3）

ARLOCK[1:0] / AWLOCK[1:0] Access type
b00 Normal access
b01 Exclusive access
b10 Locked access
b11 Reserved

Table 13-6 Atomic access encoding（AXI4）

ARLOCK / AWLOCK Access type
b0 Normal access
b1 Exclusive access

AXI4 中移除 lock 传输的理由：

  • 大多数 AXI 设备不支持 lock 传输；
  • Lock 传输为 Interconnect 设计带来了巨大的复杂度；
  • Lock 传输严重影响了 QOS 的实现。

6.2 Exclusive 操作

Exclusive 操作又称排他式操作，主要分为两大步骤：

  1. 排他式读；
  2. 排他式写。

而且要在 slave 支持排他式访问的前提下进行：

  • 第一步：Master 在排他式读的时候会将 ARlock 赋值为 1，如果 slave 支持排他式访问，会反馈 EXOKAY，master 收到 EXOKAY 的反馈以后就会知道 slave 是支持排他式访问的；
  • 第二步：接着就会发送排他式写，slave 收到排他式写命令的时候会检查写地址内容在第一步排他式读以后有没有被别的 master 写过：
    • 如果写过 → 本次排他式访问失败，slave 会反馈 OKAY，表示访问成功但是排他式访问失败；
    • 如果写地址内容没有"被污染" → 则将数据写入写地址，slave 反馈 EXOKAY 表示排他式访问成功。

Exclusive 传输的限制包括：

  • 读、写操作的长度和位宽必须相同；
  • 读、写地址必须相同且对齐；
  • ARID 和 AWID 必须相同；
  • 读、写控制信号必须相同；
  • 操作的 Byte 总宽度必须为 2 的指数倍；
  • 最大 Byte 宽度为 128 bytes；
  • AR(W)CACHE 信号必须符合原子操作的规范。

Exclusive 操作时序图（原图说明）：

  • 成功的 exclusive 操作：Master → EMT → Slave：Exclusive Read（返回 EXOK / OKAY）→ Exclusive Write（返回 EXOK / OKAY）。
  • 失败的 exclusive 操作：Master1 发出 Exclusive Read（返回 EXOK / OKAY）后，Master2 先执行了 Write 操作，随后 Master1 的 Exclusive Write 失败（Failed Exclusive Write），最终返回 OKAY。

7 AXI的outstanding

AXI 的 outstanding 是指：

  • master 没必要等待上一个操作完成就进行下一次操作；
  • 或者 slave 没必要等上一次数据处理完成才能接受下一次请求数据。

如下图所示，A21 的数据还在传输，A41 的地址就来了。

Address Channel:  A21       A41       A31
Data Channel:     D21 D22 D23 D24   D41 D42 D43
                  ↑ A21 数据尚未传完，A41 地址已发出

8 AXI的乱序传输和间插

8.1 乱序传输

乱序传输是指快速 memory 域访问没有必要等待排在它前面的访问较慢 memory 域的操作完成而完成，排在后面的可以提前完成。简单说就是，slave 返回的数据或者响应的顺序可以是和 master 发出的不一致，这样快的先返回，慢的后返回，没有等待，可以大大提高总线的效率。

之所以能支持乱序返回是由于 ID 的存在，master 可以根据 ID 来判断本次返回的 response 或者数据是哪一次发出的。所以 AXI 协议有相同 ID 之间的传输保序的要求，ID 一样的话，返回的顺序如果不保序那 master 就乱了。

ADDRESS:  A11   A21   A31
DATA:           D21 D22 D23   D31   D11 D12 D13 D14
（A31 后发但先返回；A11 先发但后返回 → 乱序）

8.2 间插

间插分为读间插和写间插：

  • 读间插：不同 ID 之间传输的数据能相互穿插，但是一个 ID 所对应的数据先后顺序不能变；
  • 写间插：不同 ID 之间传输的数据能相互穿插。

间插也是利用 ID 来识别的，不过由于 AXI4 移除了 WID，所以 AXI4 并不支持写间插。

间插示意图：地址 A0 / A1 / A2 对应的数据按 D00、D01、D10、D02、D11、D03、D20、D12、D21、D22 的顺序穿插返回。

9 非对齐传输

非对齐是指传输的起始地址和传输大小（byte 单位）是不对齐的。

比如当传输大小为 32bit（4byte）的时候，传输中每前一个数据的地址是后一个数据的地址加 4，从 0x00 开始那么起始地址要是 4 的倍数才是和传输大小对齐的。换句话说就是起始地址对应的数据 32bit 都是有效的；若不是对齐的，那么会存在某几 byte 无效。

举例：

参数 值
Address 0x07
Transfer size 32 bits
Burst type incrementing
Burst length 5 transfers

由于 0x07 不是对齐地址，所以第一次传输数据只有高 1 byte 有效，低 3 byte 无效。

Figure 10-1 Aligned and unaligned word transfers on a 32-bit bus

10 Narrow 传输

Narrow 传输是指 master 要传输的数据宽度要小于数据总线的宽度。根据 AWSIZE 和 ARSIZE 来决定传输数据的宽度。

Table 4-2 Burst size encoding

有效位（Byte Lane）计算

参数定义：

参数 含义
Start_Address 主机发送的起始地址
Number_Bytes 一次传输中传输的 Byte 数目
Data_Bus_Bytes 数据总线上面 byte lanes 的数量
Aligned_Address 对齐版本的起始地址
Burst_Length 一次突发式读写所传输的数据的个数
Address_N 每一次突发式读写所传输的地址数量，范围是 2–16
Wrap_Boundary WRAP 突发读写的低边界地址
Lower_Byte_Lane 传输的最低地址的 byte lane
Upper_Byte_Lane 传输的最高地址的 byte lane
INT(x) 对 x 进行向下取整

计算公式：

Start_Address   = ADDR
Number_Bytes    = 2^SIZE
Burst_Length    = LEN + 1
Aligned_Address = (INT(Start_Address / Number_Bytes)) × Number_Bytes
Address_1       = Start_Address
Address_N       = Aligned_Address + (N - 1) × Number_Bytes
Wrap_Boundary   = (INT(Start_Address / (Number_Bytes × Burst_Length))) × (Number_Bytes × Burst_Length)

如果有 Address_N = Wrap_Boundary + (Number_Bytes × Burst_Length)，则后面的公式成立 Address_N = Wrap_Boundary。

第一次突发式读写：

Lower_Byte_Lane = Start_Address - (INT(Start_Address / Data_Bus_Bytes)) × Data_Bus_Bytes
Upper_Byte_Lane = Aligned_Address + (Number_Bytes - 1) - (INT(Start_Address / Data_Bus_Bytes)) × Data_Bus_Bytes

除了第一次读写之后的读写：

Lower_Byte_Lane = Address_N - (INT(Address_N / Data_Bus_Bytes)) × Data_Bus_Bytes
Upper_Byte_Lane = Lower_Byte_Lane + Number_Bytes - 1
DATA[(8 × Upper_Byte_Lane) + 7 : (8 × Lower_Byte_Lane)]
