说明

本文档是 GVIM 文本编译器提高效率的一些技巧：

  • 如果你以前没有接触过 GVIM，那你需要先知道什么是 GVIM、GVIM 的一些最基本操作，然后再来看这篇文档；
  • 如果你已经用 GVIM 很久了，但是觉得自己局限于简单的操作、效率很低，那你需要看看这篇文档，最好还能看一下 GVIM 的 manual；
  • 如果你是高手，那就不用看了，或者可以进来挑挑毛病、添加一些技巧。

另外，本文档还有一个目的，就是了解 GVIM 的强大功能，开阔视野，抛砖引玉，让大家自己去开发 GVIM 的其他强大功能。毕竟我们的编程也好、查看 log 也好，都是用的 GVIM 编辑器。

GVIM 的使用是一项技能，需要的是双手，而不是理解，所以看文档时请在工作站上打开一个 GVIM 编译器，一边动手，一边看。

GVIM 的三种模式

模式 光标特征 说明
Normal 模式 光标覆盖整个字母 不管在哪种模式下，按 ESC 键（有时要 2 次）都会回到 Normal 模式。在 Normal 模式下，输入的都是命令。
Insert 模式 光标在字母之间 输入的就是屏幕上要输入的字符。
Visual 模式 光标也在字母之间，比 Insert 模式的光标粗一点 用于选择区域。

必杀技1：以一敌百

你有没有发觉很多时候我们输入的都是重复的东西，比如：

  1. always @(posedge) begin ... end
  2. if () begin: LAB_A ... end:LAB_A / else if () begin: LAB_B ... end:LAB_B / else begin: LAB_C ... end:LAB_C
  3. task xx: ... endtask: xx / function xx: ... endfunction: xx
  4. vm_note(log, $sprintf());、vm_warning(log, $sprintf());……
  5. for () begin ... end、while() begin ... end
  6. 标准的文件头
  7. task 或 function 的说明
  8. 设计中大量重复的 output、input
  9. 还有很多……

这些东西的结构内容一样，但是在编码时又都经常使用。能不能用 1、2 个字符就可以输出整个部分？可以。

方法

第一步，定义一个缩写汇总的文件，比如放在 /home/68116 下，文件名为 ab_rc.rc（文件名可以为 ab.sv、ab.v、xx.sv 都可以）：

:iab o5_ output[5:0]
:iab al_ always @()<enter>begin<enter>end
:iab if_ if ()<enter>begin<enter>end
:iab if2_ if ()<enter>begin<enter>end<enter>else if ()<enter>begin<enter>en...
:iab elseif_ else if ()<enter>begin<enter>end
:iab else_ else<enter>begin<enter>end
:iab task_ //<enter>// task name :<enter>// task purpose :<enter>//*****...

格式为：:iab a X

  • ab 是单词缩写 abbreviate 的缩写；
  • a 是缩写后的字符；
  • X 是需要被缩写的字符。例如：:iab o5_ output[5:0]。
  • 前面的 a 中不能含空格，后面的 X 中可以含空格，换行用 <enter> 表示。

这样前面所有固定的结构、需要重复输入的东西都可以定义为缩写。

第二步：在自己的 /home/68116 目录下的 .gvimrc 文件中，添加 source ~/ab_rc.rc：

source $VIM/syntax/syntax.vim
source ~/gvim.vim
source ~/ab_rc.rc
source /software/apptools/vim/6.1/menu.vim
source /software/apptools/vim/6.1/mswin.vim

第三步：试试好不好用。打开一个 gvim.sv，输入 task_，按空格或回车，效果为：

// task name :
// task purpose :
task xx();
endtask: xx

输入 if2_ 空格或回车，变为：

if ()
begin
end
else if ()
begin
end
else
begin
end

甚至输入 fh_ 空格或回车，变为文件头模板：

Project name
File Name : xx.sv
Description
Author : Liu Fujun/168116
All Right Reserved
//$log: xx.sv $

建议：由于一个缩写的后面接空格或回车都会直接展开，所以建议 :iab a X 中的 a 统一以下划线 _ 结束（如 if_、n2_……）。这样定义，真的可以做到"输入一百"。更重要的是，可以统一文件头的格式、统一编码的格式。

还可以统一 if 的书写风格（if () begin / if () 换行 / if () begin: LAB_A），统一标准的文件头，task 或 function 前强制加说明。建议验证组根据制定出的编码规范做一个这样的统一缩写模板，让大家的编码比较一致，符合验证编码规范。

必杀技2：四两千斤

如何从图1到图2？

（图1）                       （图2）
11111111111111111111         //11111111111111111111
2222222222222222222222       //2222222222222222222222
333333333333333333          //333333333333333333
4444444444444444444444      //4444444444444444444444
555555555555                //555555555555
6666666666666666            //6666666666666666
777777777777777             //777777777777777
888888888888888             //888888888888888

如果你是一次次将光标移到字符头，再一次次添加 //，那如果这种操作有 1000 行，你就要崩溃了。可以按以下操作：

  1. 将鼠标放在全 1 的那一行，回到 normal 模式（按 Esc）；
  2. 接着输入： 
    qc
^j// [Esc]j
q
  3. 接着执行 7@c。

说明：

  1. 以 q 开始，并且以 q 结束；
  2. c 代表一组操作（^j// [Esc]j）的名称，可以是任何字母；
  3. ^ 跳到光标所在行的字符头位置（参考必杀计3）；j 从 normal 模式到 insert 模式；// 插入字符；[Esc] 按 Esc 回到 normal 模式；j 跳到下一行；
  4. 7@c 执行 7 次 c 代表的命令集合，即 7 次 ^j// [Esc]j，就实现了我们的意图。

当你需要大量以比较固定格式重复的操作时，都要想想能不能用这一招，或者编写救急的简单的 perl 程序实现。

必杀计3：跳来跳去

下面的命令都是基本的移动方式，没有太多技巧，需要动手练习，直到你的手比你的脑袋先想到。这些很重要，你会在其它必杀计中经常用到。

1、上下左右

除了方向键外，请重点掌握 normal 模式下的 h j k l（不知道哪个对应上下左右？马上试试）。

2、按 word 移动（normal 模式）

命令 作用
w 右移一个 word，光标停在首字母
e 右移一个 word，光标停在尾字母
b 左移一个 word，光标停在首字母
ge 左移一个 word，光标停在尾字母

3、按行移动（常用）

命令 作用
0（数字 0）或 [home] 键 到行首
$ 或 [end] 键 到行尾
^ 到第一个非空字符

4、按屏幕移动

命令 作用
ctrl + u 向上半屏幕
ctrl + d 向下半屏幕
ctrl + f 向下一整屏
ctrl + b 向上一整屏（自己试试）

5、组合移动（常用）

比如 2j、3w 之类。2j 向下 2 行（执行 2 次 j 操作）；举一反三，3w 就是执行 3 次 w。

必杀计4：指哪打哪

在查看 log 定位问题时，有时需要在几个地方跳来跳去的看，这时这招就比较好用。

1、找字符

fx 找光标处的后一个 x。

2、找行

40G 或 :40（冒号命令，就是 normal 模式下按冒号，光标会出现在屏幕的最下一行）。注意 G 是大写（按 shift+g）。

3、找变量定义位置（常用）

有时候看代码时，需要知道变量（如 m_PacketNum）的类型、位宽等：

  • 将光标放在这个变量上，按 gd，就直接跳到定义处；
  • 按 （2 次 1），就会回到刚才的位置。` 很常用，表示跳到上次光标的位置。

4、找标记（很好用）

  • 将光标移到你需要关注的行，按 ma（以 a 标记这行，当然也可以是 m、m 等字母）；
  • 以后无论你在哪里，只要按 `a（` 可以是 1 或 enter，区别自己动手看看），就会马上跳到刚才标记 a 的行；
  • 你可以在一个文件定义很多标记，就可以指哪打哪了。

必杀计5：复制删除

在编码或文字处理过程中，会常用到删除一个字符、删除一行、将 a 行删除并复制到 b 处、复制一行等类似操作。在各种模式下都可以做到复制删除。

  • insert 模式下：和 window 下 word 里一样。
  • normal 模式下：
命令 作用
x 删除当前字符
dd / cc dd 删除一行；cc 删除一行并进入 insert 模式
yy 复制一行
p 粘贴，dd+p、yy+p 是最常用也很好用的组合
dw / cw dw 删除从当前光标到 word 尾部（包含空格）；cw 自己试试
daw / diw daw（delete a word）删除一个完整 word 即使光标不在 word 的首字符，这个比 dw 好用；diw 自己试试
das delete a sentence
d4w 或 4dw 组合键，执行 4 次 dw。还有其它很多组合，大家可以自己组合

必杀计6：自由修改

修改几乎和输入一样常用，如将 0000 修改为 0001。但是有人不管在什么 GVIM 模式下都切换到 insert 模式，然后按方向键进行修改。其实，有时候在 normal 模式下修改更简单——在 normal 模式修改并不是要显示我们会几种修改的技巧，而是节省按键次数、提高效率。

  • insert 模式下：和 word 文档中一样；
  • normal 模式下：
    • 单字母修改：normal 模式下光标移到需要修改的字符上，按 r + 修改后字符（2 次按键，比 insert 模式少 1 次）；
    • 多字符替换修改：normal 模式下按 shift + r 后，移动光标到需要修改的字符上，键入修改后字符，直到修改完，按 Esc 回到 normal（请试一下就知道了）。

另外需要提示的是，请大家尽量在 normal 模式下操作，少按几个键、少用点时间是我们的目标。其实在 insert 模式下，还有两种删除 ctrl+x、ctrl+u，请大家试试。

必杀计7：统一替换

场景：如果你想把左边 TC 列表修改为右边那样，你不会傻到一行一行去修改，更不要傻到用"列操作"，用冒号命令。

左边                                  右边
make reg TC=TC_FUNC_UFEC_0102 :UFEC0102    make run_fsdb TC=TC_FUNC_UFEC_0102 :UFEC0102
make reg TC=TC_FUNC_UFEC_0103 :UFEC0103    make run_fsdb TC=TC_FUNC_UFEC_0103 :UFEC0103
... (共 20 行)                             ...

:%s/reg/run_fsdb/gi

冒号命令就是在 normal 模式下，以冒号开头的命令。

参数解释：

部分 含义
%s 所有行，当然可以是 1,20s 即 1 到 20 行
reg 需要替换的东东
run_fsdb 替换后的东东
g 指定行的所有匹配字符，不加 g，只替换第一个
i 不区分大小写，即 am 和 AM 是一样的
c 替换时会询问，你确认后才能一个一个替换

最后可以加一些限制，如 g、i、c、e 等。

必杀计8：自动补齐

在写代码时经常要重复地写标量名，有时候为了可读性，变量名比较长，输入就很麻烦。这时可以用这招（注意细心点）。

例如你之前输入过 m_BasePacket，过了一会又要输入 m_BasePacket。这时你只需要输入 m，接着按 ctrl+p（向前找以前以 m 开头的单词，找到你想要的就松手）或 ctrl+n（向后翻）。

必杀计9：分解屏幕

有时候，你需要在一段时间在一个目录下看不同的文件，如果不断去打开（如 gvim TC_FUNC_MAC_2516.sv），就很麻烦了。有时候还需要比较一个文件中的几行或几段的区别，就需要同时能看到一个文件的两段字符。这时一种好的方法就是分解屏幕。

命令 作用
:sp 上下分解屏幕（sp 是 split 的缩写）
:vs 左右分解屏幕
:new 上下分解，打开一个新窗口
:vnew 左右分解，打开一个新窗口（自己猜）
:only 只留下光标所在窗口
:q（:close） 关掉光标所在窗口
:qall 关掉所有窗口

另外，请试一下 :vs 接着 :e .（. 为句号）。

必杀计10：进来出去

这个也常用，没有用过 GVIM 的一般都想象不到还可以这样。写 RTL 代码一定会有文件列表，验证环境中也一定有文件列表：

$SD5110V200_RTL/SD5110V200/digital_data/rtl/hdl/common_fifo/syn_byte_ff_ctrl.v
$SD5110V200_RTL/SD5110V200/digital_data/rtl/hdl/common_fifo/asyn_block_ff_ctrl.v
...

怎么从列表直接进入代码文本呢？

  • 将光标放在要看的那个文件行上，按 gf（girlfriend），（CTRL-WF）就直接进到代码文本里了；
  • 如果想回到文件列表，用冒号命令 :br（boyfriend，和 gf 对比，应该可以记住这组命令了吧），就回到列表。

必杀计11：灾后重建

如果你一不小心进入了一个比较烂的工作站，而且你又没有随时保存的习惯，突然你的 GVIM 文本被强行关掉了，导致你写的大片代码或处理过的文本毁于一旦。这时先骂一骂工作站，然后冷静一下，我们还是有一些方法来试试能不能恢复。

  • 你编辑的文本会被不断地备份在某些地方，你的文本无故被强行关掉时，会有以 .swx 为后缀的文件（如 .swp .swo .swn .swm），可以在你编译的文本当前目录键入 ll 看到。如你编译的文件名为 th.sv，这时你可能会看到 th.sv.swp；
  • 你可以输入 gvim -r 看到所有 .swx 的文件。

重建方式：

  • 再次打开 th.sv，不出意外会弹出一些对话框，就是一些 .swx 的文件信息，以及想一下这些东西： 
    [O]pen Read-Only, (E)dit anyway, (R)ecover, (Q)uit, (A)bort, (D)elete it:
  • 这时只要注意 .swx 文件的时间信息，通常选最近的那个替换文件，然后 Recover 即可。

手动方式：

  1. 用冒号命令 :rec(over)，简写或全写都可以；
  2. 会出现一些 swx 的信息，主要看看时间信息： 
    Swap files found:
Using specified name
1. .Makefile.swp
   owned by: 168116 dated: Thu Apr 10 10:22:24 2008
   file name: /nas/data2/.../sim/Makefile
   modified: no
   user name: 168116 host name: HM234
   process ID: 25345
2. .Makefile.swp ...
  3. 最后会看到提示，你可以选择你想替换的 swx（输入对应的序号）： 
    Enter number of swap file to use (0 to quit):
  4. 你检查一下这时的文本，如果是你想要的，记得赶快重新保存。当然，可能你最后键入的一点点会没有（找回 98% 也高兴得不会在乎最后几个字符被丢掉）。

必杀计12：按键映射

这个是比较强大的机制，只是大家很少用。

先提一个命令 .（中文叫"句号"），这是一个简单强大的命令，它会重复你上一次的动作。如你先 3dd（删除 3 行），发现还要删除 3 行，这时只要按 . 就又执行了一遍 3dd。

什么是键映射？ 简单的说，就是一组按键用一个键代替。

举个例子：

:map <F2> i{<Esc>ea}<Esc>

说明：

部分 含义
:map 定义键映射，冒号命令
<F2> 定义 F2，这时输入可以直接按 F2 键或输入 <F2> 四个字符
i{<Esc>ea}<Esc> 这个只能输入 <Esc> 五个字符，因为你按 Esc 键就跳出了

效果：在 normal 模式下，将光标移到 word 的首字母，按 F2 键，会在 word 前后加上 {}。因为按下 F2 键，相当于执行了 i{<Esc>ea}<Esc>。

这个像不像在 cshrc 中定义快捷键？但是请注意他们的区别：

  • :map 定义键映射，是在 normal 模式下，也就是 normal 模式下按 F2 才会执行；在其它模式下也可以定义键映射；
  • :imap 在 insert 模式下定义键映射。如上例在 insert 下定义 :imap <F2> {<Esc>ea}，则在 insert 模式下，将光标移到 word 首字符，按 F2，则同样会在 word 前后加上 {}。

GVIM 中除了 F1，其它 F2~F12 都空着可以供大家使用。至于怎么定义键映射，看你的需要和想象力。

各种模式下定义键映射：

命令 模式
:map Normal, Visual and Operator-pending
:vmap Visual
:nmap Normal
:omap Operator-pending
:map! Insert and Command-line
:imap Insert
:cmap Command-line

具体可以查 VIM 用户手册。

必杀计13：寻找

在定位时，经常需要查找某个关键词。前天还看见刚入职的一兄弟在用 Edit 菜单（VIM - Search…）在文本中查找，因此，对没有用过 GVIM 的新手我还是把这个列出来。

  • 在 normal 模式下，光标移到需要关注的 word 上，按 * 号，这时文中所有的这个 word 会被选中，以高亮显示（高亮显示需要自己定义，现在部门用的 GVIM 颜色定义一般都是高亮；如果不是，尽快向同事 copy 一个）。按 n 光标会移到下一个高亮处，按 shift+n（或打开 Capslock 键按 n，即大写的 N）会向上移动到高亮；
  • 真正查找是，按 /（这时光标在屏幕最下面一行），然后输入你要查找的字符，回车，你要查找的 word 就会以高亮显示。

例如：

  • /run：只要包含 run 的都高亮，如 run、running、run_fsdb 中的 run 都高亮；
  • /\<run\>：这个只是 run 高亮。

这个必杀计要经常结合必杀计14（匹配不匹配）使用。

必杀计14：匹配不匹配

这个是基础知识，在 perl 中也会用到，单独出来就是正则表达式的内容。什么是正则表达式？简单的说就是查看字符串，看是"匹配"还是"不匹配"。它包含的内容比较多。

注意：GVIM 中匹配和 perl 中的有差别，和文件的匹配也不一样，请不要弄混了。这些规则一般和必杀计13（查找）和必杀计7（替换）一起使用。

元字符：

表达式 含义
* 匹配前一项 0 次、1 次或多次
\+ 匹配前一项 1 次或多次
\= 前一项可有可无
\{m,n\} 匹配前一项 m~n 次
| 多选一

例子说明：

表达式 匹配内容
/a*/ 匹配 a，aa，……，还有空字符
/\(ab\)*/ 匹配 ab，abab，……，还有空字符
/a\+/ 匹配 a，aa，……
/runs\=/ 匹配 run，runs
/a\{1,3\}/ 匹配 a，aa，aaa
/foo|bar/ 匹配 foo 或 bar
/end\{if|for|while\}/ 匹配 endif，endfor，endwhile

从上面可以看出，*、\+、\=、\{m,n\}、\| 可以组合出很奇妙的匹配，大家发挥想象力。

GVIM 提供的一些特殊而强大的东东：

特殊项 匹配什么 等价的正则表达式
\d 数字 [0-9]
\D 非数字 [^0-9]
\x 十六进制数 [0-9a-fA-F]
\X 非十六进制数 [^0-9a-fA-F]
\s 空白字符 [ ]（<Tab> 和 <Space>）
\S 非空白字符 [^ ]（除 <Tab> 和 <Space> 之外）
\l 小写字母 [a-z]
\L 非小写字母 [^a-z]
\u 大写字母 [A-Z]
\U 非大写字母 [^A-Z]

必杀计15：撤销反撤销

你在撤销上次操作时是不是用的 window 中的方式，用鼠标点按钮？这样也太土了。我们要尽量抛弃鼠标。

  • 在 normal 模式下，撤销对应的是字母 u，反撤销对应的是 ctrl+r；
  • 你会发现 u 和 ctrl+r 都可以重复按，可以重复撤销/反撤销多次操作。

必杀计16：定制GVIM

你打开一个 GVIM 编辑器，里面的风格并不是天然存在的。比如你的自动缩进、一个 tab 键相当于几个空格、背景颜色、字体颜色、每行宽度、历史命令保存多少个等等，这些风格都要在 gvimrc 里定义（一般情况下，刚进部门时，都是导师 copy 一个 .gvimrc，新手比较少的人知道这些都是怎么设定的）。

.gvimrc 示例：

set hlsearch        " 高亮搜索
set mousehide       " hide the mouse pointer while typing
set undolevels=100  " set undo 100 times
set backspace=indent,eol,start
set history=100     " keep 50 lines of command line history
set ruler           " show the cursor position all the time
set showmatch
set incsearch       " 增量搜索
set showcmd         " display incomplete commands
set matchtime=10
set autoindent      " Set automatic indent of a new line
if has("vms")       " keep a backup file
  set backup
else                " do not keep a backup file, use version control
  set nobackup
endif

当你知道怎么设定时，就可以根据自己的喜好，定制一个你自己的 .gvimrc，让你的 GVIM 文本看起来有你自己的风格。

必杀计17：折起打开

有时候文本看起来很长，查找时需要翻页很多次，而且有的行我们不关心，就可以把这些行折起来。下面举个例子（将 62~79 行折叠起来）：

61 make run_fsdb TC=TC_FUNC_UFEC_0504 :UFEC0504
62 *** 18 lines: make run_fsdb TC=TC_FUNC_UFEC_0104 :UFEC0104
80 run runrrsrrrr

两种折叠方式：

  • normal 模式下，光标移到 62 行，键入 zf18j（意思是折叠光标以下 18 行）；
  • visual 模式下（normal 模式下按 v），用 hjkl 控制选中要折叠的文本，再按 zf。

相关命令：

命令 作用
zf 创建折叠
zo 打开折叠
zr 打开所有折叠，包含嵌套的折叠
zc 关闭折叠
zm 与 zr 相反

必杀计18：格式化文本

1、大小写转换

在 visual 模式（normal 模式下直接按 v 进入 visual 模式）下，按 hjkl 键选定区域：

命令 作用
U 选中区域内小写字母变大写字母
u 选中区域内大写字母变小写字母
~ 选中区域内本来大写的字母变小写字母，本来小写的字母变大写字母，和程序中"取反"操作是一样的字符，意思也差不多

2、断行

set textwidth = 72 则一行有 72 字母以后会另起一行。

3、对齐

如下例，想对齐文本：

96 make run_fsdb TC=TC_FUNC_UFEC_0404 :UFEC0404
97 make run_fsdb TC=TC_FUNC_UFEC_0501 :UFEC0501
...

需要执行 :96,100 left 0，就会成为对齐的方式。96,100 是起始行数，left 表示左对齐，0 对齐在 0 列。类似的命令还有 :96,100 right 80、:96,100 center 80。

4、自动缩进

set autoindent 和 set sw=4，你可以查看你的 home 目录下的 .gvimrc 文本。

必杀计19：全局操作

如果你想把好几个 c 文件中名为 “c_cnt” 的变量都改为 “x_counter”，这就要动到多个文件。

第一步，先把所有要改的文件放到参数列表上：

:args *.svt

该命令会找到所有的 svt 文件并开始编辑第一个。

第二步，对所有的文件都进行同一个替换操作：

:argdo %s/\<x_cnt\>/x_counter/ge | update

说明：

  • :argdo 命令以另一个命令为参数，该命令将对所有待编辑的文件都执行一次；
  • %s 替换操作将施于所有行上，它通过 \<x_cnt\> 查找 x_cnt。其中 \< 和 \> 使得只有完整的单词会被匹配，这样 “px_cnt” 和 “x_cnt2” 中的 x_cnt 才可以免遭毒手；
  • 替换操作的标志 g 使得每行中的全部 x_cnt 都被替换，标志 e 则用于避免某些文件中一个 x_cnt 都找不到时的错误消息，否则 argdo 命令遇到这些错误就会终止整个操作；
  • | 用来分隔两个命令，后面的 update 命令会在文件有改变时进行保存，如果没有一个 x_cnt 被替换为 x_counter 那就不进行任何操作。

必杀计20：由你作主

GVIM 的内容远不止上面的 19 条，上面的只是将自己认为的常用的好用总结出来，或者让大家看到 GVIM 的强大——如果工具掌握得熟练也是可以提高效率的。验证组就是要不断地提高效率，找到使人"懒惰"的方法。

  • GVIM 的熟练使用是为了少敲一些键，少花点时间；
  • VMM 架构及 CCB 的积累重用让我们少写点代码；
  • perl 的使用也是为了让机器自动地替我们做事，让我们轻松一点，“懒惰"一点。
