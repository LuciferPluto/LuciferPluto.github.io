1. 断言基本概念

1.1 什么是断言？

断言并不是一个全新的概念，在软件设计中断言早已得到了广泛的应用。它的最早的使用，可以追溯到 1949 年，在高速自动计算机会议的论文中有以下的一段叙述：

“In order that the man who checks may not have too difficult a task, the programmer should make a number of definite assertions which can be checked individually, and from which the correctness of the whole program easily flows”

断言：断言是对设计属性（feature）的描述：

  • 描述期望发生什么事情。如果实际发生与期望不同，那么这个断言失败；
  • 描述不期望发生什么事情。如果不期望发生的事情发生了，那么这个断言失败。

EDA 验证中的断言可以用 SVA 和 PSL 实现：

方式 说明
SVA System Verilog Assertions，是 System Verilog 的一个子集
PSL Property Specification Language，IEEE 1850，在 2005 年发布

1.2 断言的好处

具有独特的语法，在检验某些设计特性上比 verilog 实现具有自身的优势：描述简洁、容易维护。

例子：在当前检测到信号 a 由低变高，则接下来的 1~3 时钟周期内，信号 b 应该变为高电平。

Assertion use SV（简洁）：

a_to_b_chk: assert property
    @(posedge clk) $rose(a) |-> ##[1:3] $rose(b);

Assertion use Verilog（繁琐）：

always @(posedge a)
begin
    repeat (1) @(posedge clk)
    fork: a_to_b
        begin
            @(posedge b)
            $display("SUCCESS: b arrived in time\n", $time);
            disable a_to_b;
        end
        begin
            repeat (3) @(posedge clk);
            $display("ERROR: b did not arrived in time\n", $time);
            disable a_to_b;
        end
    join
end

1.3 断言的好处（续）

  • 断言描述的属性一般是比较简单的，并且是基于底层的信号关系，这一特性使得使用断言检查设计中的错误成为一件简单的事情；
  • 基于同样的原因，当仿真中的断言报错时，能够方便快速定位到出问题的模块和发生问题的时间，从而快速定位问题；

（配图：仿真波形中 a_p10 出现 Failure 报错标记，clk_event、a（1’b0→1’b1）、b（1’b0→1’b1）的时序关系。）

1.4 断言的好处（续2）

  • 对一些常用的检查，目前已经有了很多成熟的库，或者是别人编写的断言供我们重用，最重要的是，比起各种验证环境的组件，断言是非常容易集成；
  • 除了可以检测设计的正确性，assertion 也可以应用于 coverage。

Cover property 的例子： queue 中是否有包要调度，四种条件场景：

  1. 有 schedule_en，但是没有 queue 是 ready 的；
  2. 有 schedule_en，并且所有 queue 都是 ready 的；
  3. 有 schedule_en，有 queue 是 ready 的，但不是所有 queue 都是 ready 的；
  4. 无 schedule_en，有 queue 是 ready 的。
// Cover property
if (COVER_ON)
    sch_en_all_rdy: cover property (
        @(posedge clk) disable iff(!rst_n)
        i_input_sched_en && (&(i_input_sched_u_rdy == (NRP_0_NUM(1'b1))))
    );
    sch_en_all: cover property (
        @(posedge clk) disable iff(!rst_n)
        i_input_sched_en && (&(i_input_sched_u_rdy))
    );
    sch_en_some_rdy: cover property (
        @(posedge clk) disable iff(!rst_n)
        i_input_sched_en && (&(i_input_sched_u_rdy)) && !(&(i_input_sched_u_rdy))
    );
    sch_disen_some_rdy: cover property (
        @(posedge clk) disable iff(!rst_n)
        !i_input_sched_en && (&(i_input_sched_u_rdy))
    );
endif

1.5 断言的适用场景

场景 说明 示例
无条件的禁止 某些情况永远不允许发生 比如：fifo 永远都不能溢出
有条件的禁止 在某种条件下不允许发生 比如：控制器处于工作模式时，是不应该对 Memory 进行测试的
信号之间的互斥关系 信号不能同时成立 比如：单口的 SRAM，只能写或者读，不能同时进行读写
信号间的关系 信号间的时序/逻辑约束 比如：Ready 信号没有拉高、握手没有完成时，valid 信号不能拉低

不适用的场景：比如端到端的数据比对，设计的模块过多，检查的时间范围太大，违背了"简单"原则。

2. 常用SVA语法 & 实例

2.1 即时断言与并发断言

SVA 定义了两种断言：

类型 本质 说明
即时断言 基于事件的模拟，本质不与时序相关 一旦信号值发生改变，立刻计算逻辑表达式是否成立，必须放在过程块中
并发断言 基于时钟周期 在时钟边缘采样，然后计算逻辑表达式是否成立

即时断言：

property p1
    a && b;
endproperty

always @(*) begin
    a1: assert property(p1)
end

并发断言：

property p1
    @(posedge clk) a ##1 b;
endproperty

a1: assert property(p1)

2.2 编写断言的步骤

编写一条断言一般包括以下步骤：

  1. 编写序列（sequence）表达式；
  2. 编写属性（property）表达式；
  3. 断言属性（assert property / cover property / cover sequence / assume property）。

Sequence：

sequence BusReq(bit REQ=0, bit ACK=0);
    REQ ##[1:3] ACK;
endsequence

Property：

property P6(bit AA, BB='true, EN=1);
    @(posedge clk) disable iff(!rst_n)
    EN |-> (BB ##1 o) |=> (AA ##[1:2] (!AA));
endproperty

四种断言标签：

// label: assert property
name: assert property(P6(aa,bb,en))
    <success message>;
else
    <fail message>;

// label: assume property
name: assume property(P6(aa,bb,en));

// label: cover property
name: cover property(P6(aa,bb,en));

// label: cover sequence
name: cover sequence(BusReq(req,ack));

2.3 sequence / property 结构

sequence 语法结构：

sequence BusReq (bit REQ=0, bit ACK=0);
         ↑        ↑                  ↑
       关键字   Sequence的名字      参数表（被例化时使用，可以没有）
    REQ ##[1:3] ACK;
         ↑
    Sequence表达式，一般是一个逻辑序列
endsequence

注意：sequence 定义和 sequence 本体所在的两行结束处需要加分号。

property 语法结构：

property p_addr_stable(bit rd_en, bit wr_en, bit[ADDR_WIDTH-1:0] wr_addr);
    @(posedge clk) disable iff(!rst_n)
    wr_en ^~ rd_en |-> $stable(wr_addr);
endproperty

同样注意两个分号。property 表达式可以是逻辑表达式或者 sequence。

2.4 Clock / disable / 逻辑表达式

Clock 表达式：

  • @(posedge|negedge clk)
  • 位于 property 或者 sequence 内部；

disable 表达式：

  • disable iff(!rst_n || $isunknown(rst_n))
  • 一般位于 property 内部，可以用于解决在 DUT 未解复位时的 assertion 误报错；

逻辑表达式：

  • assertion 本质上是进行逻辑运算，判断信号组合或者时序序列成立（为 true）或者不成立（为 false）；
  • 逻辑表达式中一般使用逻辑运算符（&&、||、!=、== 等）；
  • @(posedge clk) a ##DELAY b; // DELAY 是个定值，可以用参数、宏，不能是变量；
  • ##[1:3] 代表 ##1 或 ##2 或 ##3；
  • ##[1:$] 代表从下一拍开始直到永远（仿真结束）。
property P4;
    @(negedge clk) disable iff (rst)
    (c) |-> (##[max-1:$] d);
endproperty

2.5 蕴含（Implication）操作符

交叠蕴含（overlapped implication）|->：

  • a |-> b：a 为 1 的时候，检查同拍 b 是否为 1；如果 a 为 0，则不检查 b；如果 a 为 1 而 b 不为 1，则报错；
  • 左边叫"先行算子"（antecedent），右边叫"后续算子"（consequent），先行算子和后续算子可以是逻辑表达式，也可以是 sequence。

非交叠蕴含（non-overlapped implication）|=>：

  • a |=> b：a 为 1 的时候，检查下一拍 b 是否为 1；如果 a 为 0，则不检查下一拍 b 的值；如果 a 为 1 而下一拍 b 不为 1，则报错。

要点：

  • 用蕴含符号来设置检查的门槛条件，避免每一拍都进行检查，提高仿真效率；
  • a |=> b 和 a |-> ##1 b 具有相同的含义；
  • 蕴含可以嵌套：a |-> b |-> c 是允许的，要求 a、b、c 同时为 1 时，才会检查成功；a 和 b 有一个为 0 时，不作检查。

2.6 系统函数（一）

函数 说明
$rose(a) 检测信号上升沿，相当于 a && !a_ff
$fell(a) 检测信号下降沿，相当于 !a && a_ff
$stable(a) 检测信号无跳变，相当于 a ~^ a_ff
$onehot(a) 检查信号是否有且仅有 1 bit 为 1
$onehot0(a) 检查信号最多仅有 1 bit 为 1，可以为全 0
$isunknown(a) 检查信号的值是否为 X 或 Z
$countones(a) 返回向量中值为 1 的 bit 的数量

示例：

assert property(@(posedge clk) $countones(bus) < 5);

2.7 系统函数（二）—— $past

$past(a[, b, cl])：表达信号过去 b 拍的值，相当于 a_ff1、a_ff2……a_ffb；$past(a) 表示过去一拍的值；c 为 clock gating 信号。

property p19;
    @(posedge clk) (c && d) |->
    ($past(a && b, 2) == 1'b1);
endproperty;

2.8 重复运算符（一）：连续重复

重复运算符的运算结果，实质上是一个序列。

连续重复：

signal or sequence[*n]
  • n 为一个常数；
  • a[*n]：a 连续 n 拍为真；
  • (a ##1 b ##1 c)[*3] 等价于 (a ##1 b ##1 c) ##1 (a ##1 b ##1 c) ##1 (a ##1 b ##1 c)；
  • 连续重复要求中间无中断，中断则不成立。

2.9 重复运算符（二）：跟随重复与非连续重复

跟随重复（goto repetition）：

signal or sequence[->n]
  • n 为一个常数；
  • a[->n]：n 拍为真，不必连续，不带尾巴；
property p26;
    @(posedge clk) $rose(a) |-> ##2 (b[->3]) ##1 c;
endproperty;

非连续重复（non-consecutive repetition）：

signal or sequence[=n]
  • n 为一个常数；
  • a[=n]：n 拍为真，不必连续，带尾巴；
property p27;
    @(posedge clk) $rose(a) |-> ##2 (b[=3]) ##1 c;
endproperty;

2.10 sequence 操作符：and 与 intersect

and：两个序列必须有相同的起始点，但是可以有不同的结束点，结束点为最后结束的序列的结束点。

sequence s27a;
    @(posedge clk) a ##[1:2] b;
endsequence
sequence s27b;
    @(posedge clk) c ##[2:3] d;
endsequence
property p27;
    @(posedge clk) s27a and s27b;
endproperty
a27: assert property(p27);

intersect：和 and 类似，不同的是 intersect 构造要求连接的两个序列有相同的起始点和相同的结束点。

property p21;
    @(posedge clk) s27a intersect s27b;
endproperty

2.11 sequence 操作符：or 与 throughout

or：两个序列，只要有一个成功则为真。

sequence s12a;
    @(posedge clk) a ##[1:2] b;
endsequence
sequence s20b;
    @(posedge clk) c ##[2:3] d;
endsequence
property p29;
    @(posedge clk) s12a or s20b;
endproperty
a29: assert property(p29);

throughout：检查右边序列持续的时候，左边的表达式要一直为真。

property p_no_req_0_two_gnt_1;
    @(posedge clk) disable iff (rst)
    req[0] ##1 (!gnt[0] throughout (gnt[1][->2])) |-> 0;
endproperty
a_no_req_0_two_gnt_1: assert property (p_no_req_0_two_gnt_1);

2.12 sequence 操作符：within

within：格式为 seq1 within seq2，表示 seq1 在 seq2 起始点和结束点之内成立。

sequence s32a;
    @(posedge clk) ##1 (c[->3]) ##1 (a && b);
endsequence
sequence s32b;
    @(posedge start) ##[5:10] $rose(start);
endsequence
sequence s32;
    @(posedge clk) s32a within s32b;
endsequence

property p32;
    @(posedge clk) $fell(start) |-> s32;
endproperty
a32: assert property(p32);

3. SVA的集成与仿真控制

3.1 SVA 的编写位置

SVA 可以写在 module 和 interface 内部，不能写在 class 中：

  • 写在 module 内部可以有两种方式：
    1. 写在 RTL 文件内部，用宏和 verilog pragma 隔开，一般由设计人员编写；
    2. Assertion 写在单独的 module 中，以独立文件的方式存在，用 bind 方式与 RTL module 进行连接，这种方式 assertion module 会成为 RTL module 的一个 sub instance，一般由验证人员编写；
  • 写在 interface 中，直接检查 interface 中的信号，一般由验证人员编写。

分工示意（原图）：

设计人员 (Designer)：      子模块 A/B/AA/BB 的断言 → A_chk.sv / B_chk.sv / AA_chk.sv / BB_chk.sv
验证人员 (DV)：            DE 需要将断言写入 RTL 代码；DV 需要将断言代码写入单独的文件
模块关系：Sub-block A/B/AA/BB → Block C / CC → C_chk.sv / CC_chk.sv

3.2 用 bind 将断言与模块绑定

将断言检验器与模块、模块的实例或者一个模块的多个实例绑定：

Design “fifo.v”：

`include "defines.h"
module fifo(input clk, rst_n, read, write,
            input [FIFO_WIDTH:0] data_i,
            output [FIFO_WIDTH:0] data_o);
    always @(posedge clk)
    begin
        if (rst)
            ...
    end
endmodule

Assertion “assert_fifo.v”：

module assert_fifo(clk, rst_n, read, empty);
    input clk, rst_n, read, empty;
    //do not underflow FIFO
    no_underflow: assert property (
        @(posedge clk) disable iff(!rst_n)
        empty |-> read
    );
endmodule

绑定（bind）：

module binds_list();
    bind fifo assert_fifo assert_fifo_inst(clk, rst_n, read, empty);
endmodule

3.3 在 interface 中定义断言

interface cpu_if(input bit cpu_clk); // one clock per clock domain
    //define synchronous and asynchronous signals as logic
    logic cpu_cs_n;
    logic cpu_rd_n;
    logic cpu_wr_n;
    logic [15:0] cpu_addr;
    wire  [31:0] cpu_data;
    logic cpu_rdy_n;
    logic rst_n;

    //Define default setup & hold times
    parameter INPUT_SKEW = 1ns;  // time unit is defined by timescale
    parameter OUTPUT_SKEW = 1ns;

    clocking cpu_cb @(posedge cpu_clk);
        default input #INPUT_SKEW output #OUTPUT_SKEW;
        input cpu_cs_n;
        input cpu_rd_n;
        input cpu_wr_n;
        input cpu_addr;
        output cpu_rdy_n;
    endclocking

    modport cpu_mp(clocking cpu_cb, output rst_n);

    //assert avm interface timing assertions in write operation
    assert_tcdwd: assert property (@(posedge cpu_clk) disable iff ((!rst_n) | $isunknown(rst_n))
        $fell(cpu_wr_n) |-> ##8[0:20] $fell(cpu_rdy_n))
        else $error("The timing of cpu_rdy_n tie-low is wrong in write operation");
    assert_tcdwd: assert property (@(posedge cpu_clk) disable iff ((!rst_n) | $isunknown(rst_n))
        $rose(cpu_wr_n) |-> ##8[0:8] $rose(cpu_rdy_n))
        else $error("The timing of cpu_rdy_n tie-high is wrong in write operation");
endinterface
